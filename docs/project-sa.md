# 系統分析

## 使用案例

1. 依序或跳著選第 0～3 階段課程，閱讀 Claude 或 GPT 撰寫的完整教材（不需中途填入或貼台詞）。
2. 播放一句日文做聽寫練習，打出來後對照答案並看出錯在哪。
3. 用持續循環直到停止的跟讀模式練發音與語速，不含調速。
4. SRS 單字卡複習高頻詞彙與課程生字，進度存在瀏覽器。
5. 查口語轉換表，把教科書日文對應到動畫常見的口語縮約與語氣詞；讀內建的動畫與遊戲名句與口語解說。
6. 在手機把網站安裝成 PWA（加入主畫面），全螢幕開啟、離線可讀已快取的教材。
7. 換裝置或換瀏覽器開啟，SRS 進度與已完成紀錄要能接續（2026-09-29 起改為需求，見下方「PWA 與跨裝置同步」）。

## 契約

- curriculum/lessons.mjs 為課程階段、順序、內容的單一來源。
- 教材內容（例句、單字、文法說明）由 Claude 或 GPT 一次寫完整，不設計「使用者中途填空」的資料流程。
- 動畫台詞匯入（手動貼上或 .srt/.ass 匯入）不是核心資料來源，屬於之後才決定是否做的選配功能。
- 動畫與遊戲名句是內建教材（`lessons.mjs` 的 `quotes`）：單句短台詞、必須標出處與解說、音檔自製，不收長段對白、不用原配音。
- `audioReady: false` 的課程只顯示文字，畫面標示「音檔待產生」，聽寫與跟讀不收錄。目前所有課程的音檔都已合成，沒有課程標 false；機制保留給之後新增、音檔還沒合成的課。
- completed 表示曾經成功完成的練習；後續教材修改不抹除歷史，但目前結果可能標示過期。
- localStorage 故障時仍允許閱讀教材與練習，但清楚顯示無法儲存進度。
- 音檔／語音來源需符合第 8 節版權原則：不重現購買或串流平台的原始配音音檔，教材例句音檔以自製或授權明確的 TTS 為主。

## 風險

2026-10-02 動畫特訓契約（T37／T38）：特訓也是第 2 階段課程，透過 lessons.mjs 提供，引用已有動畫短台詞及來源，不另造作品對話。作答前不揭示原文、讀音、翻譯、角色與查證連結；選項是意思，播放成功後才能作答。作答後揭示出處與既有解說。熟悉程度與播放次數是當次回饋，曾答對的理解紀錄沿用本機儲存與同步。對照台詞不與同課示範重複，但不保證使用者沒看過。完整文法、武器與技能詞彙仍為 T38 待完成，不能將 T37 的大意選擇題稱為完整特訓教材。

本機進度可被使用者自行修改，不是任何形式的能力認證。SRS 演算法與聽力教材只是學習輔助，不保證通過 JLPT。語音辨識或聽寫比對可能有誤判，回饋以文字對照為主，不做語音辨識自動評分。

## PWA 與跨裝置同步

參考另一個既有的 PWA 專案的架構，但簡化：nihongo-lab 只有一位使用者，不需要審核新登入與推播通知。（2026-10-01 更新：為了在手機與多台電腦之間同步，改用 Google 登入，但只放行使用者自己的帳號。）

- **PWA**：manifest.json + icon + service worker，快取教材文字，離線可讀課程；音檔需要使用者事先在課程頁按「下載音檔」才會存進快取（播放不會自動存檔，見 project-sd.md「離線音檔」）；沒下載的音檔離線時顯示明確錯誤，不是空白或卡住。
- **跨裝置同步**：只同步 SRS 進度與 completed 紀錄，不同步教材內容（教材本來就在 repo 裡，`git pull` 就有）。用 Cloudflare Worker 當同步端點，資料存 Cloudflare KV。
- **Google 登入，只放行本人**：頁面用 Google 登入取得身分憑證，Worker 驗證後只接受設定好的那一個帳號（email 放 Worker secret，不進公開 repo）。原本寫的「每台裝置產生隨機 ID 當識別碼」只能辨識單一裝置，連不起手機與電腦，所以不採用。
- **合併規則**：逐筆比更新時間，新的贏（細節見 project-sd.md「進度格式」「合併」）。進度檔匯出／匯入（T28）是同一套格式，兼作備份。
- 離線或 Worker 打不通時，先寫本機 localStorage，之後背景重試同步；本機永遠是可用的最後防線，不因同步失敗卡住學習。
